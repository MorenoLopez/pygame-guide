Pygame Learning Guide

Learn Pygame by building a complete Mario-like platformer from scratch

Python 3.8+ Pygame 2.x Beginner Friendly

Introduction

Pygame is a set of Python modules designed for writing video games. It provides functionality for creating windows, handling input, drawing shapes, playing sounds, and managing images — everything you need to build 2D games.

This guide will teach you Pygame step by step, and by the end, you will have built a complete platformer game similar to classic Mario. The game includes:

  • A player character with idle, run, and jump animations
  • Platform collision and gravity physics
  • Enemy AI with patrol behavior
  • Collectible coins with floating animation
  • Multiple levels loaded from text maps
  • A smooth camera that follows the player
  • Game states: Menu, Playing, Paused, Game Over, Victory
Tip

You do not need prior game development experience. Basic Python knowledge (variables, functions, classes) is enough to follow along.

Installation

First, make sure you have Python 3.8 or newer installed. Then install Pygame:

pip install pygame

1Window & Game Loop

Every Pygame application starts with three things: initializing Pygame, creating a window, and running a game loop that updates and draws everything every frame.

The Game Loop Pattern

The game loop is the heartbeat of any game. It runs continuously until the player quits:

import pygame
import sys

# 1. Initialize Pygame
pygame.init()

# 2. Create a window (width, height)
screen = pygame.display.set_mode((800, 600))
pygame.display.set_caption("My First Game")

# 3. Create a clock to control frame rate
clock = pygame.time.Clock()

# 4. Game Loop
running = True
while running:
    # --- Event Handling ---
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # --- Update Logic ---
    # (move objects, check collisions, etc.)

    # --- Draw Everything ---
    screen.fill((30, 30, 50))  # Dark blue background
    # draw your game objects here...

    # 5. Flip the display (show what we drew)
    pygame.display.flip()

    # 6. Limit to 60 frames per second
    clock.tick(60)

# 7. Clean up
pygame.quit()
sys.exit()
Key Concept

The loop has three phases: Handle Events (input), Update (logic), Draw (rendering). This pattern is universal in game development.

Understanding the Clock

clock.tick(60) pauses just long enough to maintain 60 FPS. If your game runs too fast, everything will appear sped up. The clock ensures consistent speed across different computers.

pygame.display.flip()Update the full screen surface
clock.tick(fps)Limit game to target frame rate

2Surfaces & Drawing

In Pygame, everything you draw is a Surface — a rectangular area of pixels. The screen itself is a surface. You can create new surfaces, draw on them, and blit (copy) them onto other surfaces.

Creating and Filling Surfaces

# Create a transparent surface (32x32 pixels)
surf = pygame.Surface((32, 32), pygame.SRCALPHA)

# Fill it with a color (R, G, B)
surf.fill((255, 100, 50))  # Orange-red

# Draw it on the screen at position (100, 200)
screen.blit(surf, (100, 200))

Drawing Shapes

Pygame provides functions to draw basic shapes directly on any surface:

# Rectangle: (surface, color, rect, width=0)
pygame.draw.rect(screen, (50, 200, 50), (100, 100, 50, 80))

# Circle: (surface, color, center, radius, width=0)
pygame.draw.circle(screen, (255, 215, 0), (300, 200), 25)

# Line: (surface, color, start_pos, end_pos, width=1)
pygame.draw.line(screen, (255, 255, 255), (0, 0), (800, 600), 3)

# Polygon: (surface, color, point_list)
pygame.draw.polygon(screen, (200, 50, 50), [(400,100), (350,200), (450,200)])
Important

Drawing is not persistent. Every frame, you must redraw everything. If you only draw once, it will disappear on the next frame when screen.fill() covers it.

Colors in Pygame

Colors are tuples of (Red, Green, Blue) with values from 0 to 255:

  • (255, 0, 0) — Red
  • (0, 255, 0) — Green
  • (0, 0, 255) — Blue
  • (255, 255, 255) — White
  • (0, 0, 0) — Black
  • (135, 206, 235) — Sky Blue

3Images & Sprites

Real games use images, not just colored rectangles. Pygame makes loading and displaying images straightforward.

Loading Images

# Load an image file
player_img = pygame.image.load("assets/images/player.png")

# Convert for faster drawing (recommended for all images)
player_img = player_img.convert()

# For images with transparency, use convert_alpha()
player_img = pygame.image.load("assets/images/player.png").convert_alpha()

# Scale an image
player_img = pygame.transform.scale(player_img, (64, 64))

# Flip horizontally
player_img_flipped = pygame.transform.flip(player_img, True, False)

The Sprite System

Pygame provides a Sprite class that makes organizing game objects much easier. A Sprite is an object that has an image and a rect (rectangle for position and size).

class Player(pygame.sprite.Sprite):
    def __init__(self, x, y):
        super().__init__()
        self.image = pygame.image.load("player.png").convert_alpha()
        self.rect = self.image.get_rect()
        self.rect.x = x
        self.rect.y = y

    def update(self):
        # Move the player
        self.rect.x += 2

Sprite Groups

Sprite Groups let you update and draw many sprites at once:

# Create a group
all_sprites = pygame.sprite.Group()

# Add sprites
player = Player(100, 200)
all_sprites.add(player)

# In the game loop:
all_sprites.update()      # Calls update() on every sprite
all_sprites.draw(screen)  # Draws every sprite on the screen
Why Use Sprites?

Sprites automatically handle the image and rect relationship. Groups provide collision detection, layer ordering, and batch operations. They are the standard way to manage game objects in Pygame.

4Keyboard Input

Games need responsive controls. Pygame offers two ways to handle keyboard input: event-based (for one-time presses) and state-based (for held keys).

Event-Based Input (One-Time Press)

Use this for actions that should happen once per key press, like jumping or pausing:

for event in pygame.event.get():
    if event.type == pygame.KEYDOWN:
        if event.key == pygame.K_SPACE:
            print("Jump!")
        elif event.key == pygame.K_ESCAPE:
            print("Pause menu")

State-Based Input (Held Keys)

Use this for continuous movement, like running left or right:

keys = pygame.key.get_pressed()

if keys[pygame.K_LEFT] or keys[pygame.K_a]:
    player.rect.x -= 5  # Move left
if keys[pygame.K_RIGHT] or keys[pygame.K_d]:
    player.rect.x += 5  # Move right

Common Key Constants

KeyConstant
Arrow Leftpygame.K_LEFT
Arrow Rightpygame.K_RIGHT
Arrow Uppygame.K_UP
Spacepygame.K_SPACE
Escapepygame.K_ESCAPE

0-9pygame.K_0 to pygame.K_9
Common Mistake

Do not put movement inside KEYDOWN events. If the player holds the key, the event only fires once. Use key.get_pressed() for continuous movement.

5Animation

Animation in games is simply showing different images in sequence. We cycle through frames based on time or movement state.

Frame-Based Animation

class Player(pygame.sprite.Sprite):
    def __init__(self, x, y):
        super().__init__()
        # Load all animation frames
        self.frames = [
            pygame.image.load("run1.png"),
            pygame.image.load("run2.png")
        ]
        self.frame_index = 0
        self.animation_timer = 0
        self.image = self.frames[0]
        self.rect = self.image.get_rect()
        self.rect.x = x
        self.rect.y = y

    def update(self):
        # Increment timer every frame
        self.animation_timer += 1

        # Change frame every 8 frames (at 60 FPS = ~7.5 changes/sec)
        if self.animation_timer > 8:
            self.animation_timer = 0
            self.frame_index = (self.frame_index + 1) % len(self.frames)
            self.image = self.frames[self.frame_index]

State-Based Animation

In our platformer, we switch animations based on the player's state:

def animate(self):
    if not self.on_ground:
        self.image = self.images['jump']
    elif self.vel_x != 0:
        # Running animation
        self.animation_timer += 1
        if self.animation_timer > 8:
            self.animation_timer = 0
            self.animation_frame = 1 - self.animation_frame
        self.image = self.images[f'run{self.animation_frame + 1}']
    else:
        self.image = self.images['idle']

    # Flip if facing left
    if not self.facing_right:
        self.image = pygame.transform.flip(self.image, True, False)
Pro Tip

Use pygame.transform.flip() instead of duplicating left-facing sprites. It saves memory and keeps your asset folder clean.

6Physics & Collision

A platformer needs gravity, jumping, and solid ground. We implement simple physics and use AABB collision (Axis-Aligned Bounding Box) to keep the player on platforms.

Gravity and Velocity

Instead of directly setting position, we use velocity variables:

# In the player class
self.vel_x = 0   # Horizontal velocity
self.vel_y = 0   # Vertical velocity (affected by gravity)

GRAVITY = 0.6
JUMP_STRENGTH = -12
MAX_FALL_SPEED = 12

def update(self):
    # Apply gravity
    self.vel_y += GRAVITY
    if self.vel_y > MAX_FALL_SPEED:
        self.vel_y = MAX_FALL_SPEED

    # Move by velocity
    self.rect.y += self.vel_y

Collision Detection

We check collision separately for horizontal and vertical movement:

def _check_collision(self, platforms, direction):
    for platform in platforms:
        if self.rect.colliderect(platform.rect):
            if direction == 'x':
                if self.vel_x > 0:
                    self.rect.right = platform.rect.left
                elif self.vel_x < 0:
                    self.rect.left = platform.rect.right
                self.vel_x = 0

            elif direction == 'y':
                if self.vel_y > 0:
                    # Landing on top
                    self.rect.bottom = platform.rect.top
                    self.vel_y = 0
                    self.on_ground = True
                elif self.vel_y < 0:
                    # Hitting head on bottom
                    self.rect.top = platform.rect.bottom
                    self.vel_y = 0

Why Check X and Y Separately?

If you move diagonally and check collision once, you cannot tell which side you hit. By separating axes, you can correctly resolve: hitting a wall stops horizontal movement, but landing on ground stops vertical movement.

How It Works

1. Move horizontally → check X collisions → resolve
2. Move vertically → check Y collisions → resolve
3. If landing on a platform, set on_ground = True
4. Only allow jumping if on_ground is True

7Tilemaps & Levels

Instead of hardcoding every platform position, we use a tilemap — a grid of characters where each character represents a tile type.

Level Map Format

We use ASCII art to design levels. Each character has a meaning:

# = Grass block (solid)
B = Brick block (solid)
? = Question block (solid, can be hit)
. = Dirt block (solid, underground)
P = Player start position
E = Enemy
C = Coin
F = Flag (end of level)
^ = Cloud (decoration)
* = Bush (decoration)
M = Mountain (decoration)
  = Empty space

Parsing the Level

We read the map string and create game objects based on each character:

class Level:
    def __init__(self, level_data):
        self.platforms = pygame.sprite.Group()
        self.enemies = pygame.sprite.Group()
        self.coins = pygame.sprite.Group()
        self.player_start = (100, 300)
        self._parse(level_data)

    def _parse(self, level_data):
        lines = level_data.strip().split('\n')

        for row_idx, line in enumerate(lines):
            for col_idx, char in enumerate(line):
                x = col_idx * TILE_SIZE  # 32 pixels per tile
                y = row_idx * TILE_SIZE

                if char == '#':
                    self.platforms.add(Platform(x, y, 'grass'))
                elif char == 'B':
                    self.platforms.add(Platform(x, y, 'brick'))
                elif char == 'P':
                    self.player_start = (x, y)
                elif char == 'E':
                    self.enemies.add(Enemy(x, y))
                elif char == 'C':
                    self.coins.add(Coin(x, y))
                elif char == 'F':
                    self.flags.add(Flag(x, y))
Why Tilemaps?

Tilemaps let you design levels in a text editor. You can see the entire level layout at a glance, and modifying a level is as easy as editing text. This is how many classic games (including Mario) were designed.

8Enemies & Collectibles

Enemies add challenge, and collectibles give the player goals. Both are sprites that update every frame.

Enemy AI — Simple Patrol

Our enemies walk back and forth within a set distance:

class Enemy(pygame.sprite.Sprite):
    def __init__(self, x, y, patrol_distance=100):
        super().__init__()
        self.image = load_image("enemy")
        self.rect = self.image.get_rect()
        self.rect.x = x
        self.rect.y = y
        self.start_x = x
        self.patrol_distance = patrol_distance
        self.speed = 2
        self.direction = 1

    def update(self, platforms):
        # Move
        self.rect.x += self.speed * self.direction

        # Turn around if too far
        if abs(self.rect.x - self.start_x) > self.patrol_distance:
            self.direction *= -1
            self.image = pygame.transform.flip(self.image, True, False)

        # Gravity
        self.vel_y += GRAVITY
        self.rect.y += self.vel_y

        # Land on platforms
        for platform in platforms:
            if self.rect.colliderect(platform.rect):
                if self.vel_y > 0:
                    self.rect.bottom = platform.rect.top
                    self.vel_y = 0

Coin with Floating Animation

Coins bob up and down using a sine wave:

import math

class Coin(pygame.sprite.Sprite):
    def __init__(self, x, y):
        super().__init__()
        self.image = load_image("coin")
        self.rect = self.image.get_rect()
        self.rect.x = x
        self.rect.y = y
        self.base_y = y
        self.float_offset = 0

    def update(self):
        self.float_offset += 0.1
        self.rect.y = self.base_y + int(math.sin(self.float_offset) * 4)

Mario-Style Stomp

When the player hits an enemy from above, the enemy dies:

for enemy in enemies:
    if self.rect.colliderect(enemy.rect):
        # Stomp: falling AND hitting the top half of enemy
        if self.vel_y > 0 and self.rect.bottom <= enemy.rect.centery + 8:
            enemy.kill()          # Remove enemy
            self.vel_y = -8      # Bounce up
            self.coins += 5      # Bonus points
        else:
            self.take_damage()

9Camera & Scrolling

A camera follows the player and offsets everything we draw. This creates the illusion of a large world that scrolls as the player moves.

Camera Concept

The camera is a rectangle representing the visible portion of the world. To apply the camera, we subtract the camera's position from every object's position before drawing.

class Camera:
    def __init__(self, width, height):
        self.camera = pygame.Rect(0, 0, width, height)
        self.smoothness = 0.1

    def apply(self, entity):
        # Offset entity's rect by camera position
        return entity.rect.move(self.camera.topleft)

    def update(self, target):
        # Center camera on target (player)
        x = -target.rect.centerx + SCREEN_WIDTH // 2
        y = -target.rect.centery + SCREEN_HEIGHT // 2

        # Clamp to level bounds
        x = min(0, x)
        y = min(0, y)
        x = max(-(self.width - SCREEN_WIDTH), x)
        y = max(-(self.height - SCREEN_HEIGHT), y)

        # Smooth interpolation (lerp)
        self.camera.x += int((x - self.camera.x) * self.smoothness)
        self.camera.y += int((y - self.camera.y) * self.smoothness)

Drawing with Camera

Every draw call uses camera.apply(sprite) to get the screen position:

# In the draw method:
for platform in level.platforms:
    screen.blit(platform.image, camera.apply(platform))

screen.blit(player.image, camera.apply(player))
Smooth Camera

Instead of snapping the camera instantly to the player, we use linear interpolation (lerp): camera += (target - camera) * 0.1. This creates a smooth, professional follow effect.

10UI & Game States

Games have multiple states: Menu, Playing, Paused, Game Over. We use an Enum to track the current state and draw different screens accordingly.

Game State Enum

from enum import Enum

class GameState(Enum):
    MENU = 0
    PLAYING = 1
    PAUSED = 2
    GAME_OVER = 3
    LEVEL_COMPLETE = 4
    VICTORY = 5

State Machine in the Game Loop

class Game:
    def __init__(self):
        self.state = GameState.MENU

    def _handle_input(self, event):
        if event.type == pygame.KEYDOWN:
            if self.state == GameState.MENU:
                if event.key == pygame.K_SPACE:
                    self.load_level(0)
            elif self.state == GameState.PAUSED:
                if event.key == pygame.K_ESCAPE:
                    self.state = GameState.PLAYING

    def _draw(self):
        if self.state == GameState.MENU:
            self.draw_menu()
        elif self.state == GameState.PLAYING:
            self.draw_game()
        elif self.state == GameState.PAUSED:
            self.draw_game()
            self.draw_pause_overlay()

Drawing Text

Pygame uses pygame.font to render text:

# Create a font (None = default font, 36 = size)
font = pygame.font.Font(None, 36)

# Render text to a surface
text_surface = font.render("Game Over", True, (255, 0, 0))

# Center it on screen
text_rect = text_surface.get_rect(center=(SCREEN_WIDTH//2, SCREEN_HEIGHT//2))
screen.blit(text_surface, text_rect)

Semi-Transparent Overlays

For pause menus, we draw a dark overlay over the game:

overlay = pygame.Surface((SCREEN_WIDTH, SCREEN_HEIGHT))
overlay.fill((0, 0, 0))
overlay.set_alpha(160)  # 0 = fully transparent, 255 = fully opaque
screen.blit(overlay, (0, 0))

11Full Game Breakdown

Now let's look at how all these pieces fit together in our complete platformer. The game is organized into logical classes, each responsible for one aspect.

Architecture Overview

  1. Game — Main class, owns the window, clock, and state machine
  2. Level — Parses tilemap, manages all world objects
  3. Player — Handles movement, animation, collision, lives
  4. Enemy — Patrol AI, gravity, platform collision
  5. Camera — Smooth follow, world-to-screen conversion
  6. UI — HUD, menus, text rendering

Game Loop Flow

def run(self):
    while running:
        # 1. Process events (input)
        for event in pygame.event.get():
            self._handle_input(event)

        # 2. Update game logic
        self._update()

        # 3. Draw everything
        self._draw()
        pygame.display.flip()

        # 4. Maintain frame rate
        self.clock.tick(60)

Player Update Sequence

Inside Player.update(), this happens every frame:

  1. Read keyboard state for movement
  2. Apply jump if on ground and space pressed
  3. Apply gravity to vertical velocity
  4. Move horizontally, resolve X collisions
  5. Move vertically, resolve Y collisions, detect landing
  6. Check enemy collisions (stomp or take damage)
  7. Check spike collisions
  8. Collect coins
  9. Check flag (level complete)
  10. Update animation based on state
